# MiniDV на Apple Silicon

**Оцифровка MiniDV-кассет и камкордер как веб-камера со звуком на macOS 26 Tahoe — там, где Apple полностью удалила поддержку FireWire.**

Пошаговая инструкция, проверенная на живом железе: Sony DCR-PC115E → Apple Thunderbolt-адаптеры → MacBook Air M1 → macOS 26.5.2.

Обновлено 4 октября 2026: добавлен живой звук прямо из DV-потока, правильная геометрия кадра (4:3 и 16:9WIDE),
ярлык запуска одним кликом и работа виртуальной камеры в браузере.

## Что это и зачем

В macOS 26 Tahoe Apple удалила стек FireWire целиком. Бандлы `IOFireWireFamily.kext`, `IOFireWireAVC.kext`, `AppleFWOHCI.kext` формально лежат в `/System/Library/Extensions`, но это пустые скорлупки: кода в boot kernel collection нет, загрузить их невозможно. Адаптер Thunderbolt→FireWire подключается, контроллер виден на шине PCIe — и остаётся без драйвера.

Единственный путь — пользовательский драйвер [ASFireWire](https://github.com/mrmidi/ASFireWire), реализующий OHCI 1394 на DriverKit. Проект экспериментальный, но на нём удалось получить и побитовую копию ленты, и живое видео.

Инструкция закрывает два сценария:

1. **Архивная оцифровка** — точная копия кассеты в файл `.dv` без потерь, с таймкодом и метаданными.
2. **Веб-камера** — камкордер как системная камера в Zoom, FaceTime, Photo Booth, Safari.

## Требования

### Железо

| Компонент | Модель | Примечание |
|---|---|---|
| Камкордер | Sony DCR-PC115E (MiniDV, PAL) | Подойдёт любой DV с i.LINK |
| Кабель | FireWire 400 4-pin ↔ FireWire 800 9-pin | 4-pin в камеру |
| Адаптер 1 | Apple Thunderbolt → FireWire (A1463) | Внутри LSI/Agere FW643, PCI `11c1:5901` |
| Адаптер 2 | Apple Thunderbolt 3 (USB-C) → Thunderbolt 2 (A1790) | Однонаправленный |
| Mac | MacBook Air M1 (MacBookAir10,1 / T8103) | Любой Apple Silicon с Thunderbolt |

**Порядок сборки жёсткий:** A1790 в Mac → в него A1463 → в него FireWire-кабель → в камеру. Наоборот не работает.

### Софт

| Что | Версия | Зачем |
|---|---|---|
| macOS | 26.x Tahoe | Проверено на 26.5.2 (25F84) |
| Xcode | 26.x | Полноценный, не Command Line Tools |
| Metal Toolchain | отдельный компонент | `xcodebuild -downloadComponent MetalToolchain` |
| Homebrew | — | Для ffmpeg |
| ffmpeg | 8.x | Проверка и транскод |
| OBS Studio | 32.2.1+ | Виртуальная камера (только для живого режима) |

### Место на диске

**13 ГБ на час ленты.** 60-минутная кассета в SP ≈ 13 ГБ в сыром `.dv`.

## Часть 1. Подготовка системы

Драйвер собирается локально и подписывается ad-hoc — без нотаризации. Чтобы система его запустила, нужно отключить SIP.

> **Внимание.** Отключение SIP снижает защиту всей системы. Не оставляйте машину в этом состоянии дольше, чем нужно, и не пользуйтесь в это время банковскими приложениями.

### 1.1 Отключить SIP

1. Выключить Mac **полностью** (не перезагрузка).
2. Зажать кнопку питания до надписи «Загрузка параметров запуска» → **Параметры** → выбрать пользователя → пароль.
3. Меню **Утилиты → Терминал**:

```bash
csrutil disable
```

Подтвердить `y`, ввести пароль администратора, затем:

```bash
reboot
```

### 1.2 Включить developer mode

После загрузки:

```bash
csrutil status
# System Integrity Protection status: disabled.

sudo systemextensionsctl developer on
```

> Developer mode нужен **только на время установки драйвера**. После установки его следует выключить — иначе он ломает виртуальную камеру OBS (см. [Грабли](#грабли-и-решения)).

### 1.3 Проверить, что адаптер виден

Подключите оба переходника (камеру пока не нужно):

```bash
ioreg -p IOService -w0 | grep -i "11c1"
system_profiler SPThunderboltDataType | head -40
```

Ожидается строка вида `pci11c1,5901@0 <class IOPCIDevice ... registered, matched, active>` и «Thunderbolt to FireWire Adapter» в списке Thunderbolt-устройств. Если ноды нет — проблема в кабелях или порядке переходников, дальше идти бессмысленно.

## Часть 2. Драйвер FireWire

### 2.1 Metal Toolchain

В Xcode 26 компилятор Metal вынесен в отдельный загружаемый компонент. Без него не соберётся Syphon (Часть 4), а заодно и ряд других зависимостей:

```bash
xcodebuild -downloadComponent MetalToolchain
```

### 2.2 Клонировать и собрать

```bash
mkdir -p ~/Developer && cd ~/Developer
git clone https://github.com/mrmidi/ASFireWire.git
cd ASFireWire

sudo xcode-select -s /Applications/Xcode.app/Contents/Developer
sudo xcodebuild -license accept
```

### 2.3 Применить патч

**Обязательный шаг для камкордеров.** Здесь два варианта.

**Полный патч** — живой захват, звук, геометрия, флаги диагностики, ярлык и камерное расширение. Он же содержит фикс скорости ответов S100, описанный ниже:

```bash
cd ~/Developer/ASFireWire
git checkout 9055449                      # коммит, на котором снят патч
git apply ../minidv-apple-silicon/patches/asfw-minidv-live.patch
```

Разбор содержимого — [`patches/README.md`](patches/README.md), проверка применения — [`patches/verification.txt`](patches/verification.txt).

**Только фикс скорости** — если живой режим не нужен, достаточно его (он же лежит готовым файлом: [`patches/01-responsesender-s100.patch`](patches/01-responsesender-s100.patch)):

```bash
sed -i '' 's/constexpr uint8_t kSpeedS400 = 0x02;/constexpr uint8_t kSpeedS400 = 0x00;  \/\/ S100 responses/' \
  ASFWDriver/Async/Tx/ResponseSender.cpp
grep -n "kSpeedS400" ASFWDriver/Async/Tx/ResponseSender.cpp
```

В `ASFWDriver/Async/Tx/ResponseSender.cpp` скорость исходящих async-ответов зашита константой S400. Камкордеры i.LINK работают только на S100 и физически не принимают такие пакеты — AV/C разваливается, Config ROM читается через раз. Должно стать `= 0x00`. Подробности — в [`docs/asfirewire-bugs.md`](docs/asfirewire-bugs.md).

### 2.4 Собрать и подписать

```bash
./build.sh --config Release
./sign.sh
```

> **Никогда не собирайте с флагом `--scsi`.** При отсутствии SBP-2-устройства на шине это приводит к панике ядра в бут-луп. Для камкордера SCSI не нужен.

Признак успеха — последняя строка:

```
[OK] Signed .../ASFW.app (ad-hoc, entitlements embedded).
```

### 2.5 Установить

```bash
cp -R build/DerivedData/Build/Products/Release/ASFW.app /Applications/
open /Applications/ASFW.app
```

Кнопка **Install** находится в тулбаре окна справа сверху, горячая клавиша **⌘I**.

Расширение уйдёт в состояние `activated waiting for user` — одобрить вручную:

**Системные настройки → Основные → Объекты входа и расширения → Расширения драйверов** → включить **ASFW**.

Проверка:

```bash
systemextensionsctl list
# net.mrmidi.ASFW.ASFWDriver ... [activated enabled]

ioreg -p IOService -w0 -l -r -n "pci11c1,5901" -d 2 | grep -Ei "ASFWDriver|IOUserServerCDHash"
```

Под PCI-нодой должен появиться дочерний `ASFWDriver`. `IOUserServerCDHash` — надёжный способ проверить, что загружена свежая сборка: версия бандла при пересборке не меняется, а хеш меняется всегда.

### 2.6 Выключить developer mode

После успешной установки:

```bash
sudo systemextensionsctl developer off
```

Драйвер продолжит работать — проверено. А виртуальная камера OBS без этого режима перестанет плодить дубли расширения.

## Часть 3. Оцифровка кассет

### 3.1 Подготовка лент

- Дайте кассетам сутки полежать в комнате, если они хранились в холоде или сырости.
- Перед первой кассетой прогоните чистящую кассету, дальше — каждые 8–10 часов записи.
- **Оцифровывайте той же камерой, которой снимали** — юстировка головок у каждого аппарата своя.
- Не перематывайте на максимальной скорости до упора: это главный источник зажёвывания.
- Если лента скрипит или осыпается — ловите один чистый проход, второго может не быть.
- Сдвиньте на кассете защиту от записи в положение SAVE.

### 3.2 Настройки камеры

| Параметр | Значение | Почему |
|---|---|---|
| Питание | **Сетевой адаптер** | Просадка батареи в середине кассеты = обрыв захвата |
| POWER | **VCR** | Режим воспроизведения |
| `MENU → VCR SET → A/V→DV OUT` | **OFF** | Это сквозной аналог→DV, при чтении ленты не нужен |
| `MENU → OTHERS → A.SHUT OFF` | **NEVER** | Иначе камера уснёт на паузе |
| Подключение кабеля | **при выключенной камере** | Горячее подключение FireWire — способ сжечь порт i.LINK |

### 3.3 Захват

```bash
caffeinate -d -i        # в отдельном окне — не давать Mac уснуть
```

1. ASFW → вкладка **Controller Status** → **Connect**.
2. Вкладка **DV Capture**.
3. **Channel** = `63` (камкордеры вещают широковещательно на 63-м изохронном канале).
4. **Choose Output File…** → осмысленное имя, например `2003-08_отпуск_кассета-04.dv`.
5. **Start Capture**, затем **Play** — в приложении или пальцем на камере.

Захват идёт **в реальном времени**: час ленты = час ожидания.

> AV/C-команды (Play/Stop/Rewind) до камеры доходят, но приложение может показать «no FCP response» — это [известный баг](docs/asfirewire-bugs.md) сопоставления транзакций, а не отказ. Смотрите, поехала ли лента.

### 3.4 Контроль во время захвата

| Счётчик | Норма | Если не так |
|---|---|---|
| System | `PAL (625/50)` | NTSC на европейской ленте — разбираться до продолжения |
| Isoch packets seen | ≈8000/с | 0 → камера не вещает или IR-контекст занят |
| DV source packets | 7500/с (300 на кадр) | Меньше — потери на шине |
| Non-DV packets | 0 | >0 → фильтр CIP не узнаёт поток |
| Frames | +25/с | Отставание = потери |
| Dropped frames | 0, допустимы единицы | Растёт постоянно → приём не справляется |
| Ring overruns | 0 | >0 → приложение не успевает вычитывать кольцо (буфер 1,1 с) |
| Written | ≈3,6 МБ/с | Арифметика: `кадры × 144000 = байты` |

### 3.5 Проверка результата

```bash
F=~/Documents/tape01.dv
python3 -c "import os,sys;s=os.path.getsize(sys.argv[1]);print(s,'bytes |',s/144000,'frames | remainder',s%144000)" "$F"
ffprobe -hide_banner "$F"
```

**Остаток от деления обязан быть 0** — это главный признак того, что кадры выровнены и файл цел.

`ffprobe` должен показать `dvvideo, yuv420p, 720x576 [SAR 16:15 DAR 4:3], 25 tbr`.

Проверить вторую звуковую дорожку (12-битный режим пишет две, вторая обычно пуста):

```bash
ffmpeg -hide_banner -i "$F" -map 0:a:0 -af volumedetect -f null - 2>&1 | grep mean_volume
ffmpeg -hide_banner -i "$F" -map 0:a:1 -af volumedetect -f null - 2>&1 | grep mean_volume
```

Уровень около `-91 dB` = дорожка пустая.

### 3.6 Производные файлы

Мастер `.dv` — точная копия ленты. Его **не редактируют, не пережимают и не удаляют**; всё остальное пересоздаётся из него.

**Монтажный мастер — ProRes HQ, обе звуковые дорожки, поля сохранены:**

```bash
ffmpeg -i "$F" -map 0 -c:v prores_ks -profile:v 3 -vf "setfield=bff" \
  -c:a pcm_s16le tape01_prores.mov
```

**Для просмотра — деинтерлейс в 50p, квадратный пиксель:**

```bash
ffmpeg -i "$F" -filter_complex \
  "[0:v]bwdif=mode=send_field:parity=bff,scale=768:576:flags=lanczos,setsar=1[v]" \
  -map "[v]" -map 0:a:0 -c:v libx264 -crf 18 -preset slow -pix_fmt yuv420p \
  -c:a aac -b:a 192k tape01_view.mp4
```

> **Почему 768, а не 1024.** PAL DV имеет неквадратный пиксель. При `SAR 16:15` и кадре 4:3 правильный размер в квадратных пикселях — 720 × 16/15 = **768×576**. Ширина 1024 применяется только к анаморфному 16:9.

### 3.7 Хранение

Правило 3-2-1: три копии, на двух разных носителях, одна вне дома. Рядом с каждым мастером держите текстовый файл с заметками: что на ленте, состояние плёнки, число потерянных кадров.

## Часть 4. Живой режим: камера и звук

### Как это устроено

```
Камера (CAMERA или воспроизведение ленты)
      │  изохронный канал 63
      ▼
ASFWDriver → кольцо 480-байтных DIF-чанков в разделяемой памяти
      │
      ▼
DVLivePipeline: сборка кадра → VideoToolbox → bob-деинтерлейс
      ├── видео → SyphonOutput → Syphon-сервер «Sony DCR-PC115E»
      │            IOSurface, без копирования; кадр растянут до квадратного пикселя
      └── звук  → DVAudioExtractor (PCM из DIF-блоков) → DVAudioPlayer → BlackHole 2ch
      │
      ▼
OBS: источник «Клиент Syphon» + вход «BlackHole 2ch» → Start Virtual Camera
      │
      ▼
Chrome / Zoom / Meet: камера OBS Virtual Camera, микрофон BlackHole 2ch
```

### Почему через OBS

Собственное CMIO-расширение камеры на бесплатном Apple-аккаунте активировать невозможно. Причина глубже, чем отсутствие entitlement `system-extension.install`: камера-расширение обязано зарегистрировать Mach-сервис с именем `$(TeamIdentifierPrefix)<bundle-id>`, а у ad-hoc-подписи нет ни Team ID, ни app group — регистрировать сервис попросту не в чем. Наша сборка отвечает `OSSystemExtensionError.validationFailed (9)`.

Обход: не нужно, чтобы **ваше** расширение было подписано — нужно, чтобы кадры попали в **чужое, уже подписанное**. OBS Studio с версии 28 публикует виртуальную камеру как Camera Extension на Core Media I/O с подписью OBS Project. Syphon доставляет туда кадры через IOSurface и подписи не требует вообще.

### 4.1 Syphon.framework

```bash
cd ~/Developer
git clone https://github.com/Syphon/Syphon-Framework.git
cd Syphon-Framework
xcodebuild -project Syphon.xcodeproj -scheme Syphon -configuration Release -derivedDataPath ./build
```

**Версия критична** — нужен коммит `71351d4` (PR #103, pixel-format) или новее, иначе клиенты на OBS 32.x получают прозрачный кадр:

```bash
git merge-base --is-ancestor 71351d4b484cd2d1917867f7846a5cdca724552d HEAD && echo "фикс есть"
```

Положите фреймворк туда, где его ждёт патч:

```bash
mkdir -p ~/Developer/ASFireWire/Vendor
cp -R ~/Developer/Syphon-Framework/build/Build/Products/Release/Syphon.framework \
      ~/Developer/ASFireWire/Vendor/
```

> **Не перетаскивайте фреймворк в Xcode.** Проект ASFW генерируется XcodeGen'ом из `project.yml`, и `build.sh` вызывает `xcodegen generate` автоматически. Ссылка на `Vendor/Syphon.framework` уже добавлена патчем; любая правка через интерфейс будет стёрта при первой же сборке.

### 4.2 Собрать и подписать

```bash
cd ~/Developer/ASFireWire
xcodegen generate
./build.sh --config Release && ./sign.sh
rm -rf /Applications/ASFW.app
cp -R build/DerivedData/Build/Products/Release/ASFW.app /Applications/
```

Драйвер переустанавливать не нужно — менялась только Swift-часть приложения.

Патч добавляет в приложение диагностику, которой удобно проверять всё без камеры и без FireWire:

| Флаг | Что делает |
|---|---|
| `--list-audio-devices` | список устройств CoreAudio |
| `--audio-selftest [сек]` | тон 1 кГц (L) / 3 кГц (R) через боевой плеер |
| `--dv-audio-selftest <файл.dv> [--pcm-out <файл>]` | прогон `.dv` в темпе 25 к/с + дамп PCM |
| `--audio-render-selftest <файл.dv> --pcm-out <файл>` | тот же граф офлайн-рендером |
| `--dv-frame-selftest <файл.dv> --png <файл>` | режим кадра, растяжка, PNG |
| `--audio-device <имя\|uid\|default>`, `--no-audio` | выбор приёмника звука |

### 4.3 Звук: он уже лежит внутри DV-потока

Отдельного аудиокабеля не нужно: в каждом кадре DV 12 DIF-последовательностей, в каждой 9 аудиоблоков, и звук жёстко привязан к кадру. Синхронность с видео не восстанавливается — она есть по построению: 48 кГц → 1920 сэмплов на канал на кадр, 32 кГц → 1280, 44,1 кГц → 1764.

| Режим камеры | Что разбирается | Приёмник |
|---|---|---|
| `AUDIO MODE → 16BIT` | 16 бит/48 кГц, одна стереопара | BlackHole 2ch |
| `AUDIO MODE → 12BIT` | 12 бит нелинейные/32 кГц, первая пара (микрофон) | BlackHole 2ch |

Оба режима сверены с FFmpeg побитово (`max|d| = 0`), разбор кадра стоит 3,5 мкс.

```bash
brew install --cask blackhole-2ch            # один раз, спросит пароль администратора
ASFW=/Applications/ASFW.app/Contents/MacOS/ASFW
$ASFW --list-audio-devices
$ASFW --audio-selftest 3
```

Другой приёмник: `--audio-device "имя или UID"`; системный выход: `--audio-device default`; выключить звук: `--no-audio`.

> Почему BlackHole, а не системный выход: играя в колонки, звук с камеры не попадёт в приложения, а если сделать BlackHole системным выходом — пропадёт звук у всех остальных приложений.

### 4.4 Геометрия: 4:3 и 16:9WIDE

В DV пиксель неквадратный, а `16:9WIDE` у Sony — анаморфная запись: картинка физически сжата по ширине внутри кадра 720×576 (мануал DCR-PC115E, стр. 59). Показывать кадр надо так:

| Режим камеры | PAR | Квадратный пиксель |
|---|---|---|
| 4:3 | 16:15 | 768×576 |
| 16:9WIDE | 64:45 | 1024×576 |

Признак читается из VAUX Video Control пакета кадра (тег `0x61`) и вешается на кадр как `kCVImageBufferPixelAspectRatioKey`. Syphon PAR не передаёт вовсе, поэтому кадр уходит в него уже растянутым.

Если 16:9 показывался как 5:4 — картинка была сжата по ширине примерно на 42 % (замер по записи OBS: содержимое занимало 1344×1075).

```bash
$ASFW --dv-frame-selftest wide.dv --png wide.png
# режим кадра: 16:9 (анаморфно); извлечено 720×576 → 1024×576
```

### 4.5 Ярлык: камера, звук, OBS и виртуалка одним кликом

```bash
./tools/minidv-live/install.sh          # соберёт и поставит /Applications/MiniDV Live.app
```

Дальше — двойной клик по **MiniDV Live** (или ⌘Space → «MiniDV Live»). Ярлык проверяет драйвер и BlackHole, глушит прошлый живой захват, поднимает новый, открывает OBS, через obs-websocket добавляет в сцену источники `Sony DCR-PC115E` и `BlackHole 2ch`, вписывает видео в канву и включает виртуальную камеру. Лог: `~/Library/Logs/MiniDVLive.log`. Отладка без окон: `MINIDV_NO_DIALOG=1 "/Applications/MiniDV Live.app/Contents/MacOS/MiniDVLive"`.

Помощник ярлыка (`tools/minidv-live/obs-sources.js`) включает в OBS WebSocket-сервер сам — это единственный способ добавить источники в уже запущенный OBS. Слушает он только `127.0.0.1:4455` с вашим паролем; выключить можно в **Tools → WebSocket Server Settings**.

### 4.6 Настройки камеры для живого режима

| Параметр | Значение | Почему |
|---|---|---|
| **Кассета** | **вынуть** | С лентой камера через несколько минут расцепляет барабан головок и уходит в сон. Это защита механики, отключить нельзя |
| POWER | **CAMERA** | Живой сигнал с матрицы |
| Питание | Сетевой адаптер | |
| `MENU → OTHERS → DEMO MODE` | **OFF** | Без кассеты камера через 10 минут запускает демо-ролик и подмешивает эффекты прямо в выход i.LINK. Пункт доступен только когда лента вынута |
| `MENU → OTHERS → A.SHUT OFF` | **NEVER** | |
| Крышка объектива | снять | |

Живой режим работает и на воспроизведении ленты (POWER → VCR, Play) — тогда звук идёт в том режиме, в котором лента записана.

### 4.7 Виртуальная камера и браузер

Один раз: запустить OBS → **Start Virtual Camera** → согласиться на установку расширения → одобрить в **Системные настройки → Основные → Объекты входа и расширения → Расширения камеры** (ярлык включает её сам при каждом запуске).

```bash
systemextensionsctl list | grep -i obs
# нужна РОВНО ОДНА строка [activated enabled]
```

> **Главная ловушка.** `OBS Virtual Camera` — системное расширение, и оно **всегда** перечисляется в списке камер приложений, даже когда OBS закрыт. Кадры идут только при активном выходе виртуальной камеры: сначала **Start Virtual Camera**, и только потом выбирать её в браузере. Второе: расширение объявляет **единственный формат 1920×1080@60** — если приложение требует ровно 30 к/с, будет отказ.

Chrome кэширует список камер при старте, поэтому после включения виртуалки браузер надо перезапустить (⌘Q). Разрешения нужны на двух уровнях: macOS (Конфиденциальность → Камера/Микрофон) и сам сайт.

Диагностика: `tools/camera-test/camera-test.command` — поднимает локальный сервер и открывает страницу с превью, списком устройств, negotiated-форматом и точной ошибкой (`NotAllowedError`, `NotReadableError`, `OverconstrainedError`), плюс кнопки проверки частоты кадров. Рядом полезен `chrome://media-internals`.

### 4.8 Запуск вручную (без ярлыка)

```bash
pkill -x ASFW; sleep 2
open -a /Applications/ASFW.app --args --syphon
sleep 3
log show --last 1m --info --style compact --predicate 'category == "SyphonRunner"' | tail -3
# Syphon runner started on channel 63
```

Затем в OBS: **Источники → + → Клиент Syphon** → в свойствах выбрать **Sony DCR-PC115E** → **Start Virtual Camera**.

> **Почему по флагу, а не всегда.** Живой пайплайн занимает изохронный контекст приёма. Если бы он стартовал автоматически, оцифровка кассет перестала бы работать — они делят одно кольцо. **Живой режим и захват с ленты взаимоисключающи.**

Требование к декодеру (уже выполнено в патче): буферы должны быть IOSurface-backed и в формате BGRA — `kCVPixelBufferPixelFormatTypeKey`, `kCVPixelBufferIOSurfacePropertiesKey`, `kCVPixelBufferMetalCompatibilityKey`. Без IOSurface публикация молча пропустит все кадры, это видно по счётчику `framesSkippedNoIOSurface`.

## Часть 5. Настройки OBS

Правильные настройки важнее выбора кодека: при холсте 1920×1080 SD-картинка растягивается в FullHD и записывается размытый апскейл.

### Настройки → Видео

| Параметр | Значение |
|---|---|
| Базовое разрешение (холст) | **1024×576** для `16:9WIDE` или **768×576** для 4:3 |
| Выходное разрешение | равно базовому — тогда пересчёта нет вовсе (можно и 1920×1080: 1024×576 — ровно 16:9, апскейл без искажений) |
| Фильтр масштабирования | Ланцоша |
| FPS | **50** (bob-деинтерлейс даёт 50 обновлений в секунду) |

1024 и 768 — это кадр 720×576 в квадратных пикселях для 16:9 и 4:3 соответственно: извлекатель уже растянул картинку, чтобы Syphon не терял пропорции.

В сцене: правый клик по источнику → **Трансформировать** → **Сбросить трансформацию** (или **Вписать в экран**). Это важно после обновления приложения: разрешение источника меняется (720×576 → 1024×576), а сохранённый трансформ остаётся старым.

### Настройки → Вывод → Запись

| Параметр | Значение |
|---|---|
| Режим вывода | Расширенный |
| Тип | Обычный |
| Формат записи | Гибридный MOV (.mov) — переживает падение OBS |
| Генерировать имя файла без пробела | **включить** |
| Кодировщик видео | **свой**, не «использовать кодировщик трансляции» |
| Кодировщик звука | CoreAudio AAC |

> **Частая ошибка.** «Использовать кодировщик трансляции» означает битрейт стрима — около 2500 Кбит/с. Для 50 кадров в секунду этого мало, картинка в файле заметно хуже превью.

Выбор кодека:

| Задача | Кодировщик | Настройки | Место |
|---|---|---|---|
| Обычная запись | Apple VT H.264 (аппаратный) | CQP/CRF **18–20**, или CBR **20000** Кбит/с | 5–8 ГБ/час |
| Материал в монтаж | Apple ProRes **422** | — | ~36 ГБ/час |

ProRes 422 HQ избыточен для SD (~54 ГБ/час), 4444 бессмыслен — источник 4:2:0 без альфа-канала.

### Настройки → Дополнительно

- Цветовой диапазон: **Ограниченный**. DV-материал изначально в ограниченном диапазоне; при полном тени зальются в чёрный, а света выбьются.

### Про звук

**Syphon передаёт только видео** — звук идёт отдельным путём, прямо из DV-потока в BlackHole. Поэтому в OBS нужны два источника: «Клиент Syphon» для картинки и **Audio Input Capture** с устройством `BlackHole 2ch` для звука (ярлык добавляет оба).

Проверить, что звук вообще есть, можно без камеры: `ASFW --audio-selftest 3` — тон уйдёт в приёмник.

> Глобальный `Микр/доп` (микрофон Mac) ярлык не трогает. Если он включён, в запись попадёт и он — мут в микшере OBS.

### Оцифровка кассеты

## Часть 7. Возврат системы в исходное состояние

Порядок обратный установке, **нарушать нельзя**:

```bash
systemextensionsctl uninstall - net.mrmidi.ASFW.ASFWDriver
systemextensionsctl list                 # убедиться, что записи нет
sudo systemextensionsctl developer off   # если ещё включён
```

И только потом Recovery → `csrutil enable` → перезагрузка.

> С включённым SIP система откажется запускать ad-hoc-подписанный dext. Если расширение осталось установленным, при каждом старте остаётся осиротевший kernel-stub.
>
> **Аварийный выход:** Recovery → `csrutil disable` → загрузиться → снять расширение → Recovery → `csrutil enable`.

| Симптом | Причина | Решение |
|---|---|---|
| `cannot execute tool 'metal'` | В Xcode 26 Metal-тулчейн — отдельный компонент | `xcodebuild -downloadComponent MetalToolchain` |
| Kext-ы FireWire есть в `/System/Library/Extensions`, но не грузятся | На Apple Silicon код живёт в boot kernel collection, бандлы — пустые скорлупки | Проверять через `kmutil inspect`, а не `find` |
| `AppleFireStormErrorHandler` в выводе `kextstat \| grep fire` | Обработчик ошибок ядер M1 | К FireWire отношения не имеет |
| Расширение висит `terminating for uninstall but still running` | Старая копия держит слот | Перезагрузка |
| Непонятно, загрузилась ли новая сборка | Версия бандла не меняется | Сверять `IOUserServerCDHash` в `ioreg` |
| Правки в Xcode исчезают после сборки | Проект генерируется XcodeGen'ом | Править `project.yml`, затем `xcodegen generate` |
| `initializer for conditional binding must have Optional type` | `SyphonMetalServer` неопционален при мосте из ObjC | Убрать `guard let` |
| Флаг `--syphon` не срабатывает | `open --args` не передаёт аргументы уже запущенному приложению | `pkill -x ASFW` перед `open` |
| Лог пустой, хотя код работает | `log.info` скрыт по умолчанию | Добавить `--info` к `log show` |
| Картинка вверх ногами | Разные начала координат в OpenGL и Metal | `flipped: true` в `publishFrameTexture` |

| Захват с ленты перестал работать | Живой пайплайн держит изохронный контекст | Остановить живой режим, перезапустить ASFW без флага |

| В браузере отказ при ровно 30 к/с | Расширение OBS объявляет единственный формат 1920×1080@60 | Проверить `tools/camera-test`, использовать ideal-ограничения или другой браузер |

## Ограничения

- **SIP должен быть выключен постоянно.** Драйвер подписан ad-hoc; чтобы работать с включённым SIP, нужны entitlements `com.apple.developer.driverkit.transport.pci`, которые Apple выдаёт индивидуально по запросу с платным Developer-аккаунтом.
- **Камера как системное устройство (CMIO) не активируется.** Расширение `ASFWCamera` написано и публикует «Sony DCR-PC115E», но система отвечает `OSSystemExtensionError.validationFailed (9)`: нужна нормальная подпись (Developer ID/Development с совпадающим Mach-сервисом). Поэтому живой режим идёт через Syphon → OBS → OBS Virtual Camera и требует запущенного OBS.
- **Вторая звуковая пара (ST2) не публикуется** — разбирается только первая (микрофон). В 12-битном режиме она обычно пуста.
- **Общего таймлайна нет.** Синхронность держится на покадровом приходе; счётчика дрейфа звука и видео мы не делаем.
- **Bus reset не обрабатывается.** У Syphon-раннера есть сторожевой таймер (перезапуск при остановке потока), но выдёргивание кабеля и переключение CAMERA↔VCR — нет.
- **Живой режим и оцифровка кассет взаимоисключающи** — общий изохронный контекст.
- **AV/C-управление формально не работает** (баг 2), хотя команды до камеры доходят.
- **Сквозную задержку до браузера мы не измеряли**: по частям — разбор звука 3,5 мкс/кадр, буферы по 20 мс, дальше буфер BlackHole и формат виртуальной камеры 1080p60.
- **NTSC и DVCPRO50** извлекатель звука не поддерживает (только PAL 625/50, 144 000 байт на кадр).
- **Isochronous Receive в ASFireWire помечен как экспериментальный.** На проверочном захвате — 1 потерянный кадр из 1896, но гарантий проект не даёт. Ценные ленты стоит прогонять с контролем счётчиков.
